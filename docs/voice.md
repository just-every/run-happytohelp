# Telephone support (partial)

Voice connects verified Aircall and Twilio Voice numbers through authenticated native routes under `/api/voice/projects/:projectId`. It uses the installation's existing integration encryption key. Provider credentials are encrypted for the workspace, never returned by settings reads or carried into archives. Installing, rotating and disconnecting a number requires a current owner/admin with integration permission and recent native step-up.

This is an unfinished support feature. Do not launch a telephone number from this implementation until a held provider sandbox, provider-approved emergency number/location procedure and US jurisdiction review qualify it. The product is not emergency dispatch. Call prompts disclose that callers must hang up and dial 911 in an emergency; short-code dialing is refused here. That disclosure does not prove emergency routing.

## Connect and route

`POST /numbers` accepts `provider` (`twilio` or `aircall`), `provider_id`, `account_id`, private `token` and `settings`. Twilio uses the account SID and auth token; Aircall uses the API ID and API token. The provider's own number endpoint must verify the number. Updating an existing number also requires its current `version`; use `GET /numbers` to read it. `DELETE /numbers/:numberId` revokes the local connection and webhook admission; it does not remove a provider-owned number or subscription.

Settings specify `timezone`, same-day `hours` intervals (`day` 0–6, `start`/`end` in 24-hour time), `human_phone`, optional `aircall_user_id`, optional native `group_id`, `ivr` choices (`digit`, `label`, `phone`), `jurisdiction` (`US-` followed by the state code), and explicit `recording_enabled`, `staff_consent` (every receiving teammate has opted in), and `retention_days` (1–30, default 1). Recording cannot be enabled without that staff consent attestation. An empty hours list is closed all day. Native tickets retain a responsible group or the unassigned queue. Configure cross-midnight hours as two intervals. Holidays and per-IVR native groups are not configured here.

Set the Twilio number's incoming-call webhook to the returned `webhook_url` using POST. The request URL and form parameters must carry Twilio's account-token signature and matching account/number. Calls hear the emergency limitation and, when recording is enabled, choose 1 to consent or 2 to decline. An absent/invalid choice ends without recording. Open-hour calls choose an IVR destination or the default human phone. A failed human dial leaves visible follow-up and enters a bounded provider queue; after two minutes without a human it offers voicemail only with consent. A native transfer command can take a queued call to the configured human phone. After-hours calls offer consented voicemail, otherwise chat/email or a later call. Identical signed steps replay their committed TwiML; conflicting results cannot replace consent.

Aircall owns its routing, Smartflows, opening hours and transfers. Configure `call.created`, `call.answered` and `call.ended` webhooks for the returned URL and one-time `webhook_token`. The token is hashed locally. Incoming events must match the connected number. Ended calls cannot be rewound by a delayed creation event. Aircall recordings and transcripts are not imported because this implementation cannot attest their consent.

## Inbox, callback and history

A caller becomes a separate telephone customer; a caller number never proves the authority of an existing email/account identity. A teammate with contact-management permission can find an existing customer by email and explicitly link or unlink operator context. The link provides customer/history context only, never merges contacts or changes caller permissions. Foreign, blocked or erased customers are refused; erasure of either contact removes the link. Linking/unlinking is audited, and reads recheck current availability. Repeat calls within a workspace attach to the same telephone conversation. Automatic private call receipts make it visible in the existing inbox. These notes never enter the public chat transcript or generate public messages, email, AI replies or workflow reply events.

`GET /conversations/:conversationId/calls` reads the retained call history, consent, summary, follow-up and provider command outcomes. `POST /conversations/:conversationId/commands` accepts `kind` (`callback` or `transfer`), `call_id`, `number_id` and a stable, operator-chosen `request_id`. It requires current reply permission. A Twilio callback calls the configured human first, then bridges the customer with recording off. Aircall callbacks use its configured teammate. An accepted response means provider acceptance, not a connected customer. A 5xx, timeout or lost response stays uncertain; repeating the same command cannot dial again. Check the provider before deliberately creating a new command ID. Aircall transfers remain in its own application.

Open Settings → Telephone to connect or disconnect a number and edit routing, hours, IVR, queue, jurisdiction and media retention. Updating routing uses `PATCH /numbers/:numberId` with the current `version`, without replacing credentials or rotating the Aircall webhook token. In the inbox, open Ticket → Telephone calls for history, transcript, recording download, confirmed callback/human transfer, provider outcomes and consent withdrawal. Reports → Telephone calls loads retained call and follow-up counts. The Claude UI lane owns the visual design pass; these are functional controls in the existing dashboard.

A consented Twilio recording reference is served only through `GET /conversations/:conversationId/calls/:callId/recording`, with native conversation permission rechecked after the provider read and `Cache-Control: no-store`. Raw provider recording URLs are never exposed or fetched from webhook input. Consented voicemail transcripts arrive through the signed transcription callback. Consented Twilio human calls start Real-Time Transcription for both tracks. Signed final utterances are stored in provider sequence order with duplicate/conflicting-delivery checks and a 16,000-character/400-utterance bound. History shows the caller/teammate transcript and automatically extracts its first 600 characters as explicitly labelled verbatim highlights; these are not model-generated conclusions. Provider errors do not invent content. Real provider language/quality qualification remains pending. `GET /report` groups retained calls by provider and state with visible follow-up counts; erased customers are excluded.

## Privacy, restore and agent hook

The conservative default is all-party opt-in for every recording/transcription, independently of state law. Calls without consent are not recorded here; outbound callbacks are unrecorded. `POST /conversations/:conversationId/calls/:callId/withdraw` removes local media immediately, fences signed media callbacks and previously recorded routing responses, and asks Twilio once to complete the call. Provider acceptance is not confirmation that the call stopped or that provider copies were deleted. Lost responses remain uncertain without automatic retry; Aircall stopping and provider deletion must be confirmed in the provider account. A download rechecks withdrawal after the provider responds. Media expires after the configured number of days from admission, is hidden at that instant, and is removed by bounded hourly cleanup. Changes apply to new calls and never extend existing media expiry. Conservative default ADOPTED pending ct: one-day local media retention, optional 1–30 days, verbatim highlights only, no media carried into archives. Jurisdiction policy and the provider's separate retention still need review before launch.

Erasing a telephone customer removes caller ciphertext, provider call/recording references, transcript, summary and private receipts, and fences later signed callbacks and new calls using the retained workspace-specific phone digest. A command already sent to a provider cannot be recalled: erasure leaves an explicit external deletion task. Other customers and workspaces are preserved. Archives omit execution credentials, phone/provider-reference ciphertext, recordings, transcripts and their summaries, disable restored numbers and retain unknown commands without replay. Restored call media remains expired; only a new consented call can supply fresh media. Reconnect explicitly after restore.

AGENT-001 can use the native conversation ID and the guarded human-transfer command as its telephony hook. This module executes no AI procedure, grants no cross-channel account authority and claims no governed voice agent. Automated-agent disclosure, consistent approved procedures across voice/chat/email and AI-to-human handoff remain with that campaign.

After a restore, reconnecting a number permits newly signed calls. Archived calls cannot resume: old entry, routing and recording callbacks are refused, so a saved call step cannot restart recording or refresh callback identity.
