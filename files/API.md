# B custody integration handoff

All product exports are in `src/modules/legacy-import/custody/index.ts`. The APIs require migration `329_legacy_package_custody.sql` before serving. Missing schema fails closed. C owns its RELEASE entry and deployment integration.

- `admitCustody(env:{DB}, input:Admission): Promise<CustodyHandle>`: Admission extends `{projectId,actorId,sessionHash}` with `{sha,sourceProjectId,destinationProjectId?,mappingPolicyVersion:2}`. Caller must validate/hash the bounded original manifest and source scope first. Admission atomically registers its exact manifest key, conceals foreign custody and refuses all prior erasures/unfinished leases, including expired leases, in each scope.
- `registerKey(env:{DB}, handle:{sha,generation}, principal, kind, ordinal=0): Promise<string>`: registers the exact server-derived key under the same active custody/session batch fence. No caller-supplied arbitrary key is accepted.
- `descriptorOrdinal(kind:'chunk'|'context'|'object',file): number`; `custodyKey(sha,kind,ordinal=0): string`: only `rows-NNNNNN.json`, `context-NNNNNN.json`, `object-NNNNNN.bin` and manifest.json. Reject rather than rewrite old names.
- `putCustody(env:{DB,FILES},handle,principal,input:{kind,ordinal?,body:Uint8Array,sha256,bytes,takeover?}): Promise<{key,alreadyPresent}>`: bounded byte count/hash, registered key, random nonce CAS, current authority check, checksum-bound ETag replacement, final active check and upload retention renewal. An accepted immutable body is idempotent only after submitted bytes are validated. Occupied reservations are pending; takeover uses a fresh nonce/ETag. No loser deletes a winner.
- `sourceReady(env:{DB,FILES},handle,principal,kind,ordinal,sha256,bytes): Promise<boolean>`: requires live authority, registered key, accepted body metadata and actual stored R2 checksum/size. A nonce or ETag is never content proof. Caller must keep a custody assertion in the consumer write batch after readiness is checked.
- `custodyAssertion(db,handle,principal?): D1PreparedStatement`; `custodyBatch(env,handle,principal,statements,checkAfter=true)`; `assertCustody(...)`: C adds the package assertion to every worker scratch/canonical/checkpoint batch alongside its existing run version, live session and destination workspace lease guards. Optional principal is for composing A's already-authorized batch; omission does not grant native access.
- `destinationStatements(db,handle,destination): D1PreparedStatement[]`: include in A's approval/provenance transaction with `custodyAssertion`; source/custody IDs are never relabeled.
- `renewCustody(env,handle,principal,state:'upload'|'progress'|'paused'|'stopped'|'resume'|'complete')`: only explicit valid uploads, committed progress or named transitions renew. Complete asserts all four scratch families absent before its final 24-hour window. Every renewal is capped at seven days from first admission; status polling never renews. Persisted retention state also keeps repeated PUT/stop/complete calls from extending a stopped or completed deadline; explicit resume is required before further committed progress. Registry ready denotes valid custody, never a global package-completeness assertion: C must still scan all required descriptors and use sourceReady per file.
- `discardCustody(env,handle,principal)`: caller must require native step-up; terminal SHA closure. `closeCustody(env:{DB},sha,reason)` is the internal terminal cleanup primitive for erasure/workspace_deleted/expired/discarded, bumps package/run versions and clears source diagnostics.
- `scopeFenceStatements(db,projectId,reason:'erasure'|'workspace_deleted')`: constant-size permanent monotonic scope fence. Native contact erasure already includes it in the admitted-identity transaction. All uploaders/workers must consult it immediately, before paged run closure reaches them.
- `cleanupStep(env:{DB,FILES},sha,generation): Promise<{keys,rows,pending}>`: cleanup-only tombstone authority; at most 100 exact R2 keys and 250 scratch/parts child rows TOTAL per step. Four context families include record/media_lookup/delta_plan, messages, media links and identity ownership. Keeps canonical journals/counts/history, removes private source diagnostics and parts descriptors. Durable claims prevent simultaneous cursor advancement. Retained ordinal-only coordinates sweep harmless late nonce placeholders in purged groups.
- `cleanupScopeStep(env:{DB,FILES},projectId)`: one package quantum through the actual native erase door; returns safe pending summary. `sourceCleanupAssertion(db,projectId)` is included in canonical erasure and final provider/audit/lease completion batches; `sourceCleanupStatus(env,projectId)` returns fixed code/counts.
- `discoverCleanup(env:{DB,JOBS},limit=10): Promise<number>`: bounded indexed scope pages/expiry/due tasks, closes/enqueues at most ten; failed sends remain due. `scheduleScopeCleanup(env,projectId)` is used by workspace deletion. `enqueueCleanup(env,custody)` sends `{type:'legacy-package.cleanup',id:<sha>,generation}`. C must add the job variant to Env, dispatch cleanup BEFORE inactive-project gating, share the measured existing cron reservation and route this message to `cleanupStep`. The generic sender uses a narrow transport cast because B cannot edit Env/Job.
